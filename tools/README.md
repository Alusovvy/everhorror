# tools/

Dev tools run from the command line (project root). Not used by the game and excluded from the export.
`GODOT` below means `C:/dev/gamedev/Godot_v4.7.2-stable_win64_console.exe`.

## Workflow and documentation checks

- Current workflow and source ownership: `../specification/WORKFLOW.md`. A person starts planning, implementation and finalization.
- Dashboard runs: every agent step (`/spec-tasks`, `/ai-task analyze|implement|fix|review`, `/spec-sync finalize`) starts only with Roland's click in the spec dashboard (view Praca), as one `claude -p` child of the local server, one at a time. How to use it: `../specification/dashboard/INSTRUKCJA.md`; how it works inside: `../specification/dashboard/ARCHITEKTURA.md`.
- **Run locks** (`reports/dashboard-runs/`, git-ignored; written by `runner.ts`, D-33): one file `locks/<runId>.json` per active run (the authority; fields `runId`, `kind`, `task`, `branch`, `pid`, `startedAt`, `startedBy`, `image` (the child's executable name, to tell it from a recycled pid)). `lock.json` is only a summary for readers that know one run: the oldest run's fields plus `runs: [{runId, kind, task, pid}]`; it disappears when nothing runs. One folder per run next to them: `run.json`, `events.jsonl`, `contract.md`, `guard.log` and before/after snapshots. A terminal session must stop while any run in the summary has a live pid that is not its own.
- `pwsh -NoProfile -File tools/spec_poll.ps1 -DryRun`: reports locally known specification state, with no fetch, model launch, files, logs or registration. A normal run fetches upstream and records only the last reported notification in `reports/spec-sync/last-notification.txt`; `-LocalOnly` skips fetch. Other switches: `-Register` / `-Unregister` (create or remove the optional scheduled task "Everhorror spec-sync"; not allowed together with `-DryRun`), `-Minutes <1-1440>` (the interval for `-Register`, default 15) and `-IgnoreDirty` (kept for old callers; the notifications work with a dirty spec anyway). It never starts a model and never changes tasks, the ledger or gameplay. Registration is optional and is not done by default: do not assume the task exists.
- `pwsh -NoProfile -File tools/test_spec_poll.ps1`: checks notifications, deduplication, CLI failure and side-effect-free DryRun in temporary Git repositories, without project remotes.
- `node tools/check_doc_links.js`: checks local Markdown file targets in the specification and `CLAUDE.md`. Optional arguments select files/directories. It does not validate remote pages or heading fragments. Known: the dashboard's test fixtures (`dashboard/src/work/fixtures/`) have deliberately dead links, so "missing" there is not an error.
- Dashboard validation (from `../specification/dashboard`): `npm test`, `npm run build`, `npm run lint-spec`, and `npm run e2e` (the end-to-end test of the work flow in `node/e2e/`: the real HTTP API, run manager and guard against throwaway repositories and a fake claude, about 75 s). The remaining human checks are the rows of the open sheets in `docs/human-tasks/` (the closed PT0 sheet `factcheck-test-14.md` is in `done/`).

## Testy

**Run the full suite only after the user approves it. Never start it automatically.** The dashboard server runs `unit lint dialogue` plus the scenarios named in the task file after every implement or fix run (D-36; the whole suite on the server: `EVERHORROR_SERVER_TESTS=full` in the dashboard's environment, `off` disables it). To check a change by hand, run one short scenario (`tools/run_tests.sh unit` and `balance` take about 2 s each, `lint` about 8 s with the generator check).

The suite has five layers, all scripts that print a `RESULT` line and are run by `tools/run_tests.sh`: (1) `unit`, pure logic; (2) `lint`, static cross-checks of ids and time labels; (3) `dialogue`, every conversation without UI; (4) the world scenarios in `tools/tests/`; (5) `balance`, the balance bot. `run_tests.sh` fails a scenario whose log has no `RESULT: ALL PASSED` line **or contains an `ERROR:` / `SCRIPT ERROR:` line** that is not on the allow-list at the top of the script (the engine's exit noise: RID leaks, "resources still in use", PagedAllocator and the dummy renderer's `Parameter "material" is null`); the first offending lines are printed under the result. Logs go to `reports/tests/<name>.log`. After changing a `.dialogue` file run `--import` first (the tests read the imported version; a brand-new `.dialogue` file needs two import passes). Run `balance` after any balance change and compare the `BALANCE[...]` lines; its story gates are a simplified table of `07_balans.md` "Pomiar" in the specification, keep the two in step.

**Test folders and the `run_tests.sh` interface (G-E1).** A scenario never writes into the player's `%APPDATA%\Godot\app_userdata\Everhorror` (`auto.json`, `slot_*.json`, `raporty/`): `SaveManager` keeps `save_dir` and `report_dir`, and under a test they point into a folder of the run. The folder comes from the environment variable `EVERHORROR_TEST_DIR=<absolute path>` or the user arg `--test-dir=<path>` (after `--`); a test script started without either (`test_base.gd`, `unit_test.gd`) uses `user://test-runs/<pid>` and removes it when it ends. `run_tests.sh` gives every scenario its own subfolder `<base>/<scenario>` and deletes it afterwards, so a killed run leaves nothing in the player's folder and scenarios of several branch copies, or `-j N`, do not race for a slot. `<base>` is `$EVERHORROR_TEST_DIR` when set, else a temporary folder. Interface (the dashboard server calls it from the branch copy):

```
cd <branch copy> && EVERHORROR_TEST_DIR=<folder> tools/run_tests.sh [-j N] unit lint dialogue day1 …
```

One line per scenario, in the order asked: `name  <s>s  RESULT: …` (plus `BALANCE[…]`, `PERF[…]`, `WARNINGS: …` and `RULES: …` lines under their scenarios, and the first `ERROR:` lines under a red one); the exit code is the number of red scenarios. `-j N` runs up to N scenarios at once (default 1; the output is printed in the order asked, after they finish); `GODOT=<exe>` overrides the Godot executable. Scenarios: `unit`, `lint`, `dialogue`, `balance`, the world scenarios `tools/tests/test_<name>.gd`, and the extra ones that are **not** in the default list: `perf` (needs a window), `export` (day1 and expedition from an exported pack, see "Eksport" below), `check_generated` and `rule_coverage` (also part of `lint`). The player's `settings.cfg` is not redirected (no test saves options).

Writing scenarios: extend `res://tools/tests/test_base.gd`, implement `scenario()`, start with `start_world(setup)` where `setup` prepares `GameState` (set the `intro_done` flag to skip the intro). Use `step()`, `check()`, `converse()`, `travel()` (map table + WYRUSZ), `go_on(id)` (field map; `"oboz"` goes back), `use()`, `drive()`, `wait_for_vn()`, `wait_idle()` (it also closes the expedition summary and keeps its text in `last_summary`). Override `timeout_s` in `_init()` for longer scenarios. After a dialogue that asks a question, call `wait_for_vn()` and `drive([answers])`; `wait_idle()` only answers unexpected questions with the first option and records a failure. Every wait has a time limit and a watchdog ends the scenario with `RESULT: TIMEOUT in step '…'`. A scenario writes its saves and run reports into the test folder (`sm.save_dir`, `sm.report_dir`, `sm.slot_path(n)`); never hard-code `user://saves` or `user://raporty` in a test. Don't type variables with `class_name` types (`Npc`, `Interactable`…) in test scripts: they compile before the autoloads exist and fail.

## Build do ogrania

A playable build (D-32) is the game exported from one commit of a task branch (or master) without a version number, a CHANGELOG entry or a tag, so that a person plays the branch before the sheet. The spec dashboard makes it by itself after an implement or fix run that ended well, or on a click ("Zbuduj do ogrania"); in a terminal: `node ../specification/dashboard/cli.ts build task_NN` (or `master`), refused while a dashboard run holds the lock. It checks the commit out into a temporary worktree (`../everhorror-wt/_build-<sha7>-…`, removed afterwards) with the `.godot` import cache of the branch worktree (else of the main copy), runs `GODOT --headless --path <tmp> --import` and `--export-release "Windows Desktop" <out>`, and writes `build/do-ogrania/Everhorror-test-task<NN>-<sha7>-windows.zip` (Everhorror.exe, CZYTAJ_MNIE.txt, CHANGELOG.md, BUILD_DO_OGRANIA.txt) with a manifest `.json` and the Godot log `.log` next to it; the two newest builds of a task stay. It never runs `stamp_build.js`: the stamp would dirty a worktree and belongs to a release, so the main menu of a playable build shows the version of the last release. `EVERHORROR_GODOT`, `EVERHORROR_PLAYBUILDS_DIR` and `EVERHORROR_PLAYBUILD_AUTO=0` (no build after runs) change it. Details: `../specification/dashboard/ARCHITEKTURA.md`, "Build do ogrania (D-32)".

## Eksport (G7, G-E10)

`export_presets.cfg` keeps `export_filter="all_resources"` and excludes what is provably unused. **Exporting "selected scenes and their dependencies" was tried on 2026-10-27 and does not work in this project**: the exporter follows only what a scene or resource names, so it dropped every script used only through its `class_name` (`DMConstants`, `RunReport`, `CampSchedule`, the data classes: the game does not compile) and every asset that a script only `preload`s (the characters' base models, hair, the animation library), and the saving was small once those were put back (about 10 MB, because most of the weight is imported textures that are used). What the preset does instead:

- `exclude_filter` has a hand-written part (`reports/*`, `tools/*`, `docs/*`, `build/*`, `addons/gdUnit4/*`, `*.cs`, the Dialogue Manager example balloon) and a **generated** part: `tools/export_excludes.js --write` lists the Fantasy Props glTF models and the Mine & Caves pack scenes whose file name no scene, resource, script, dialogue or generator mentions (136 on 2026-10-27, `assets/prop_pack/Exports/glTF/<Name>.*` and `assets/LoafbrrAssets/MineAndCavesSet/…`). After you start using a model or a pack scene, run it (`lint` is red until you do, via `check_generated.js`).
- Measured on 2026-10-27, `--export-release "Windows Desktop"` on this machine: `Everhorror.exe` 238.3 MB before, 220.4 MB after (5.8 MB of the difference are the `reports/` of the main copy, which a clean branch copy does not have; the rest is the unused pack assets and the examples of an addon that task_21 later removed).
- The folders of the packs that are not used (`assets/prop_pack/Exports/FBX`, `OBJ`, `Textures`) have local, git-ignored `.gdignore` files, so Godot does not import them.
- A second preset, "Test Pack", has the same filters plus `tools/*`, for `tools/export_smoke.sh`: it runs scenarios from the exported pack. It showed that **the exported game is broken in the way the playtest ticket `zgloszenia/2026-10-27_eksport-gubi-listy.md` describes**, on the unchanged preset as well: `expedition` fails 10 checks and `hrapek` 1 from the pack, and passes from the project folder; `day1`, `drudzy` and `places` pass from the pack. With `[editor]` `export/convert_text_resources_to_binary=false` in `project.godot` the same pack passes `expedition` (verified 2026-10-27, not applied here: it belongs to the task of the ticket). So `tools/run_tests.sh export` is red until that setting (or typed arrays) is in.

## Wydanie

A release is not a playable build (above): it has a version number, a CHANGELOG entry and a tag, and is made after the merge.

Since the audit of 2026-10-27 (D-36) the dashboard makes the release: the card „Wydanie” on **Praca** (administrator) takes the new version number, runs the steps below in a temporary copy of `master` (the text of `## [Nieopublikowane]` in `CHANGELOG.md` moves under the new heading, `CZYTAJ_MNIE.txt` gets the version, stamp, import, export, zip), commits, fast-forwards `master`, tags `v<version>`, pushes and writes the version into `WDROZENIA.md` (`cli.ts ledger release`). Finalize writes each closed task's entry under `## [Nieopublikowane]`. The manual path stays:

Release steps (task_14; the current version is the newest `## [x.y.z]` heading of `CHANGELOG.md`):

1. The version is the same in three places: `application/config/version` in `project.godot`, the newest `## [x.y.z]` heading of `CHANGELOG.md` (Polish, newest first, with "Zgodność ze spec: `<sha>`" per version) and the first line of `release/CZYTAJ_MNIE.txt` ("(demo x.y.z)"). `run_tests.sh unit` and `stamp_build.js --check` fail when they differ.
2. `node tools/release/stamp_build.js`: stamps the spec commit into `script/build_info.gd`.
3. `GODOT --headless --path . --import`.
4. `GODOT --headless --path . --export-release "Windows Desktop" build/windows/Everhorror.exe`: the PCK is embedded; `reports/*`, `tools/*`, `docs*`, `build/*`, `addons/gdUnit4/*` and 136 generated entries for unused pack assets (below) are excluded; `dialogue/*.json` is included. A `.gd` file is exported without any filter, a loose `.json`/`.cfg` is not.
5. `tools/release/make_zip.sh`: `build/Everhorror-demo-<version>-windows.zip`.
6. Commit the stamp, `CHANGELOG.md` and `CZYTAJ_MNIE.txt`, tag `v<version>` (on the build commit), and write the same spec commit into the `WDROZENIA.md` entry in the specification.

Patch releases get a third number. The main menu starts a new game with the user arg `--new-game` (smoke tests).

Notes:
- Test and tool scripts load the world one frame late, because autoloads are not registered yet when a `--script` main loop starts.

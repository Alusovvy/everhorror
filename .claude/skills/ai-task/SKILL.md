# ai-task

Modes (the argument after `/ai-task`): **`status`** (default), **`analyze NN`**, **`implement NN`**, **`fix NN`**, **`review NN`**, **`close NN`**. A bare "zrób task_12" means `analyze` if the task has no resolved plan yet, otherwise `implement`.

Paths: [CLAUDE.md#places](../../../CLAUDE.md#places). Read [CLAUDE.md](../../../CLAUDE.md) first (systems: `docs/agent/README.md`; tests and release: `tools/README.md`). Rules from `docs/ai-tasks/INFO.md`: never edit the task's requirements section ("Wymagania:" / "Requierments"), typos included; the task file always ends with **Podsumowanie**, in the task's language (task_02+ Polish); report in the task file and briefly in chat.

**Dashboard lock (every mode).** Before you change anything, check it as described in [CLAUDE.md#dashboard-lock](../../../CLAUDE.md#dashboard-lock). If another live run holds it, stop and report who; never delete it.

Process and source precedence: `C:/dev/gamedev/everhorror/specification/WORKFLOW.md` (solo mode, 2026-10-26). Roland owns all active sections; keep original authorship and attribute chat decisions. Never fill a human zone (list and rules: [docs/human-tasks/INFO.md](../../../docs/human-tasks/INFO.md#strefy-człowieka)); your automated checks go only in the task report or under `## Wyniki automatu (agent)` in the sheet. A merge or a green check is not human verification: playtests stay pending until a person's result or Roland's explicit waiver. A new gameplay request first becomes accepted spec text, then a task with its spec SHA (plan §3 pkt 2, `docs/analizy/final-plan-human-readable.md`); never implement it directly on main. A bounded documentation/tooling request follows its authorized scope, without starting gameplay stages (etapy).

Helpers in `.claude/agents/` get the working directory, the files and one concrete question, return only conclusions and never edit: `lore-checker` (Polish lines or world facts vs. the canon), `test-runner` (named scenarios → RESULT table; wait for it), `convention-reviewer` (the diff vs. `CLAUDE.md`).

## Dashboard runs
You are in one when `EVERHORROR_DASHBOARD_RUN` is set or the appended system prompt starts with `# Przebieg z dashboardu`. Roland's click started you: the skill call is the whole job. The appended Polish contract names the task, branch, paths and limits and ends with Roland's note, verbatim; the note never lifts a rule, and a stricter contract wins over this file. `WDROZENIA.md` is changed only with `node C:/dev/gamedev/everhorror/specification/dashboard/cli.ts ledger …` (never by hand); the contract lists the operations allowed for the run kind. A PreToolUse guard blocks forbidden commands and writes (a block is a rule, look for no workaround); an audit flags violations afterwards, nothing is reverted.
- **Non-interactive.** Never ask or wait. When Roland has to decide, write one decision card (D-03) `C:/dev/gamedev/everhorror/specification/zgloszenia/<YYYY-MM-DD>_task<NN>-<topic>.md` (ASCII name) from `szablony/decyzja.md`: `Rodzaj: decyzja`, `Zadanie: task_NN`, one table `| # | Pytanie | Opcje | Rekomendacja | Twój wybór |` for all questions (recommendation first, `Twój wybór` empty), `## Decyzja` = "Do rozstrzygnięcia." Every option must be understandable without the rest of the card: it says in words what is chosen, and every code (B1, A2…) it uses is explained either by a list item `- B1: …` under "Możliwości i rekomendacja" (the dashboard shows it next to the question) or on the spot (`**a)** B1 (scena zaznaczenia żyły) + B2 (przyciemnienie przy pracy)`). A gloss after the last code only does not explain the earlier ones (`B1 + B2 (najmniejszy krok)` leaves B1 unexplained). A code with neither triggers the lint warning `OPCJA_KOD_BEZ_OPISU` (rule ids like CZAS-10 are exempt): fix it before committing. At most five open cards (plan §3). Lint (`node C:/dev/gamedev/everhorror/specification/dashboard/cli.ts lint`, 0 errors), commit the card as `[agent] …` naming only its path, link it from the task file, stop with `STATUS: czeka-na-decyzje`. Never guess or go on past the question. A `review` run writes no card: it states the open decision in `podsumowanie` with the verdict `blokada`.
- **Main copy.** Never switch its branch, commit, merge, push or tag in it. Docs you create or change there (report, sheet) stay uncommitted: Roland saves them with "Zapisz dokumenty w historii gry". Do not `git mv` task files or sheets (`/spec-sync finalize` moves the task file after the merge; Roland's click closes a sheet).
- **Code** only in the worktree named in the contract, on the task branch (the dashboard makes one worktree per branch in `C:/dev/gamedev/everhorror/everhorror-wt/`; older branches may stand in `everhorror-wdrozenie`); Godot only with `--path` set to it. Tests by name through `test-runner`; the full suite only when the contract says "user approved full suite".
- **Spec commits** only after lint shows 0 errors (full path form above), with explicit paths: `git -C <spec> add -- <file>`, then `git -C <spec> commit -m "[agent] …" -- <file>`; never `-a`, `add -A`, `add .`. Pushing the spec `master` is allowed (standing permission), never forced. Tickets and cards stay in `zgloszenia/`: edit with Edit and Write, never `git mv`, `mv`, `cp` or `rm` (the guard blocks it; finished ones move to `zamkniete/` outside a dashboard run).
- **Commands.** Always `git -C <full path> …`. No `git -c`, `bash -c`, `eval`, `node -e`, variables or `$(…)` in paths. Merge, rebase, reset, checkout, stash, clean, tag and force push are blocked, as are network, MCP and PowerShell (also npm, npx).
- **Human zones and requirements.** Never write a human zone; the task's requirements stay byte-identical (hook blocks, audit checks). The audit also checks what a sheet says about itself (`SHEET_STATE`): never add or change the header notes `zastąpione …` and `niesprawdzone przez człowieka` or a `Zwolnienie:` line, rename a human column (`wynik` to `Wynik automatu`), put `(agent)` in the heading of a human table, or delete a sheet's empty rows. The hook cannot tell these from prose; the audit can.
- **Finish** with exactly three Polish lines: `STATUS: ok|czeka-na-decyzje|blad`, `ZROBIONE: <one sentence>`, `NASTĘPNY KROK: <what a person or the next run does>`. `blad` also covers a failed precondition. `review` ends with its JSON verdict, no STATUS lines.

## status
One line per `docs/ai-tasks/task_*.md` (not `done/`): title or first requirement, source (spec or chat; for a spec task its branch and "W zadaniach" status) and what it waits for: analysis; a decision (open card with `Zadanie: task_NN`, or a legacy `decision-task-NN.md`); another task ("Kolejność"); implementation; review or fixes of its branch; the user's sheet; closing. Also list sheets whose `wynik` column is filled in (ready for `close`). Change nothing.

## analyze NN
1. Read the task, `INFO.md`, any factcheck or decision of a task it depends on, and the code and spec parts it touches ("Dla agenta"). If an earlier task ("Kolejność") is still open, say so.
2. Below the requirements (after the `---` / agent marker) write **Analiza** (how it works today, gaps, risks) and **Plan** (steps, files, tests, spec/docs updates).
3. Open questions: interactive → AskUserQuestion; unattended or a dashboard run → a decision card (D-03), linked from the task. Legacy `decision-task-NN.md` files are read-only history.
4. Report in chat: what the task needs, what you ask.

## implement NN
A task with the header line `Źródło: specyfikacja` was written by `/spec-tasks`; also follow **Spec tasks**.

1. **Preconditions.** Every decision is resolved (cards with `Zadanie: task_NN` ✅ or closed, a legacy file in `human-tasks/done/`, or the user answered in chat); dependencies are implemented; a filled-in sheet of a related task has been read, its bugs fixed or out of scope. Otherwise stop and say what (dashboard run: `STATUS: czeka-na-decyzje` for a decision, else `blad`).
2. **Implement** following the conventions in `CLAUDE.md` (generators for generated scenes, Silesian keys, dialogue tags, DIA-2 guards, number helpers, `--import`).
3. **Lore.** New or changed Polish lines, or facts about people, places, magic or factions: spawn `lore-checker` with the lines (`file:line`) and the facts they assert. Fix real contradictions; route unresolved canon to Roland with sources and a recommendation, keeping deliberate unknowns and `[ROBOCZE]`.
4. **Tests.** `test-runner` with `unit lint dialogue` plus the scenarios of the touched systems (map: `tools/README.md`); say whether `.dialogue` files or new `class_name` scripts changed (it must `--import` first). A fresh worktree needs Godot's `--headless --path <worktree> --import` before any test. The full suite only when the user approved it in this conversation (pass "user approved full suite"). Fix failures caused by the change; report others instead of widening it.
5. **Review.** `convention-reviewer` on the uncommitted diff, naming the task; fix findings, re-run `test-runner` on the scenarios they touch.
6. **Docs.**
   - Sheet `docs/human-tasks/factcheck-test-NN.md` (Polish): in the **main copy**, never on the branch; from `factcheck_template.md`, or `playtest_template.md` for a play session (rules: `docs/human-tasks/INFO.md`). Human zones stay empty; in an existing sheet add rows and prose only. **An open sheet that nobody has started grows instead of a new one (D-27):** when the main copy already holds an open sheet whose human cells are all empty (no entry, no `Wyniki człowieka`, `Zwolnienie` or `Zamknięcie` line), do not create `factcheck-test-NN.md`. Append this task's part at the very END of that sheet (never in the middle: table numbers and answer ids of the entries above must stay put): a `## Część: task_NN — <title>` heading with its own "Co zostało dodane", "Test" and "Wyniki automatu (agent)", human cells empty. Add `task_NN` to the header line `> Zadania: [task_16](../ai-tasks/task_16.md), [task_NN](../ai-tasks/task_NN.md) · …` (turn the old `> Zadanie:` line into `> Zadania:` first). The "Na gałęziach" row of `WDROZENIA.md` then names that shared sheet. A sheet a person has started to fill in is never extended: create a new one as before. The dashboard offers the sheet for entries only once it has a current playable build of the branch (D-32). Never export, zip or stamp the game by hand (no `tools/release/stamp_build.js` on a task branch): in a dashboard run the dashboard makes the build after the run; in a terminal session without the dashboard, after the commit on the branch, run `node C:/dev/gamedev/everhorror/specification/dashboard/cli.ts build task_NN` (about a minute; it refuses while a dashboard run holds the lock).
   - The old duplicated design docs were removed (D-02) and `docs/archiwum/MECHANICS.md` is history: no sync duty. Where each went, with the last commit: spec `WORKFLOW.md#starsze-źródła`.
   - Spec: update the rules; mark self-decided details **[ROBOCZE]**; code pointers under "Dla agenta"; numbers in `07_balans.md`. Add **no new row** to "Zmiany agenta poza specyfikacją" (D-23, plan §9, agent recommendation, subject to Roland's veto): an urgent fix of a bug that violates an existing rule needs none, since it restores conformity; any other game change is first a ⬜ rule. Lint the spec (0 errors). A local-only documentation task neither commits nor pushes; otherwise follow the current authorization.
   - Update where the changed fact lives: `CLAUDE.md` (rules, conventions), `docs/agent/README.md` (systems), `tools/README.md` (tests, release).
7. **Task file.** Fill in "Co zostało zrobione" (one subsection per requirement), "Decyzje i założenia", "Czego potrzebuję od Ciebie", "Test" (link to the sheet, RESULT lines), "Podsumowanie" last. Then move it to `docs/ai-tasks/done/`: first `git ls-files --error-unmatch docs/ai-tasks/task_NN.md` (a file outside the history is saved first: Roland's "Zapisz dokumenty w historii gry" or an `[agent] proces` commit), then `git mv`. Links inside the quoted requirements stay as they are (like `done/task_13.md`); its other relative links gain one `../`. Fix incoming links (the task link in the sheet's header → `../ai-tasks/done/task_NN.md`). A spec task stays in `docs/ai-tasks/` until its branch is merged; a dashboard run never moves a task file.
8. **Report** in chat, briefly: changes, test results, what to check in the sheet, open questions.

## Spec tasks
Tasks with `Źródło: specyfikacja <sha7>`, created by `/spec-tasks`. They differ from chat tasks as follows:
- **Where.** Branch `spec/<YYYY-MM-DD>-task<NN>` in its own worktree; never switch branches in the main copy. In a dashboard run the branch and its worktree already exist and are switched (the contract names them): create and switch nothing. In a terminal: `git -C <game> worktree add -b spec/<date>-task<NN> C:/dev/gamedev/everhorror/everhorror-wt/spec-<date>-task<NN> master`, then copy `.godot` (`cp -r <game>/.godot <worktree>/`) or run `godot --headless --path <worktree> --import`. At most one open `spec/*` branch: a 🔧/🧪 row in "Na gałęziach" (`WDROZENIA.md`) means stop and name it. Give the worktree path to `test-runner` and `convention-reviewer`.
- **Requirements** are rule quotes; the spec text of those IDs (and "Dla agenta") is binding. A self-decided detail goes into the spec as **[ROBOCZE]**. If the spec contradicts itself, ask (interactive) or write a decision card; don't guess.
- **Commit** code and current docs on the branch as `task_NN: <short Polish summary>`, IDs in the body. The sheet is **not** committed there (the dashboard commits it from the main copy); an older one already on the branch (task_14's PT0) stays, report it. Standing permission covers `spec/*` commits. Never commit to or merge into `master`. The report goes into the task file in the main copy, which stays in `docs/ai-tasks/` until the merge and `/spec-sync finalize`.
- **Spec.** One command writes both ledger rows (never edit `WDROZENIA.md` by hand): `node <spec>/dashboard/cli.ts ledger set-branch --branch spec/<date>-task<NN> --commit <sha7> --changes "<IDs>, task_NN" --sheet docs/human-tasks/factcheck-test-NN.md --status do-sprawdzenia --task-status na-galezi`. That adds the "Na gałęziach" row (🧪 do sprawdzenia) and sets the task's "W zadaniach" row to 🧪. `--sheet` is the sheet from the sheet step: when the sheet grows (D-27), it is the existing shared sheet. Don't flip ⬜→✅ (finalize does) and add no row to "Zmiany agenta poza specyfikacją". Lint, commit `[agent] spec/<date>-task<NN>: wdrożone na gałęzi, do sprawdzenia` with explicit paths, push.
- **Tool and documentation tasks** (`Rodzaj: narzędzia` / `dokumentacja`) have no spec rules or spec commit, but the same branch, worktree, report and sheet. Use the same `ledger set-branch` command with `--commit —` (a real hash would move the start of `/spec-tasks` and the baseline) and `--changes "task_NN"`. They get no "W zadaniach" row (intro of that section; the command only warns that it skipped `--task-status`) and never start gameplay.
- **Report** in chat with how to try it: the playable build `build/do-ogrania/Everhorror-test-task<NN>-<sha7>-windows.zip` (the dashboard makes it after the run; in a terminal see step 6), then the sheet. Merging stays Roland's click ("Scal do master gry").

## review NN
Read-only review of a built branch (the dashboard's "Przegląd" click; also fine in a terminal). It writes and commits nothing.
1. Find the branch and the worktree (a contract names them). Read `git -C <worktree> diff master...<branch>` (also `--stat`; `show <branch>:<path>` for whole files), the task's requirements and report in the main copy, and the sheet. Never switch the worktree or the main copy. If the worktree is not on the branch (`branch --show-current`), skip the tests and say so. A fresh worktree needs `--headless --path <worktree> --import` before the tests.
2. Judge against: every requirement; the spec rules of its IDs and "Dla agenta" (pointers right, `[ROBOCZE]` on self-decided details, numbers in `07_balans.md`, both ledger rows at 🧪); the decisions it relies on; the `CLAUDE.md` conventions; the process rules (sheet in the main copy, human zones empty, requirements byte-identical, the report ends with "Podsumowanie").
3. You may spawn `convention-reviewer` (range `master...<branch>`) and `lore-checker`, and run named short tests through `test-runner` (`unit lint dialogue` plus the touched scenarios). Never the full suite.
4. Final answer, nothing after it: one JSON object `{werdykt, wymagania, ustalenia, podsumowanie}`: `werdykt` = `gotowe` (no `błąd`, every requirement `spełnione`, named tests pass), `poprawki`, or `blokada` (must not be merged: a human zone filled, requirements edited, a decision missing, a test failing because of the change); `wymagania` = per requirement `{nr, stan: spełnione|częściowo|brak, dowod}` (file, line or test); `ustalenia` = `{waga: błąd|uwaga, plik?, linia?, opis}`, most serious first (`błąd` must be fixed before the merge); `podsumowanie` = two or three Polish sentences for Roland. A dashboard run passes the schema (`--json-schema`): return the object via structured output, no STATUS lines. In a terminal print a JSON block.

## fix NN
Corrections on a built branch (a 🧪 row in "Na gałęziach"). Inputs: the run note (Roland's note verbatim: review findings and/or the ❌/💬 rows), the task report, the sheet (read only).
1. The branch `spec/<date>-task<NN>` exists and is not merged. Its own worktree (named in the contract) stands on the branch and is clean; if not, stop and report. Only an older branch in the shared worktree (`everhorror-wdrozenie`) may be detached and clean, then `git -C <worktree> switch <branch>`. A fresh worktree needs `--headless --path <worktree> --import` before the tests.
2. Fix only what the findings name, following `CLAUDE.md`. A finding that needs a design decision, or a ❌/💬 row asking for something new, is not a fix: dashboard run → decision card (`STATUS: czeka-na-decyzje`), terminal → ask. New gameplay goes through the spec first.
3. `test-runner` on the touched scenarios (plus `unit lint dialogue` when lines or ids changed), never the full suite without approval; `convention-reviewer` on a non-trivial diff.
4. Append `## Poprawki (<RRRR-MM-DD>)` to the task report in the main copy: what each finding got (fixed, or why not) and the actual test results. Touch the spec only if a rule, a `[ROBOCZE]` detail or a "Dla agenta" pointer changed (lint, `[agent]` commit with explicit paths, push).
5. Commit on the branch as `task_NN: poprawki …`. Do not call `ledger` in a fix (the row stays 🧪). Never fill, clear or re-mark a human zone; the ❌/💬 rows stay as written, and the person re-checks. The dashboard makes a new playable build of the branch head after the run (terminal: `cli.ts build task_NN`); the sheet waits for it.

## close NN
The normal path is the dashboard (Praca → the sheet): a person fills it in ("Wypełnij arkusz"), then "Przenieś arkusz do done/", or waives it ("Zwolnij z testu"), each a click and one signed commit. This mode is for a terminal session when Roland asks, never a dashboard run.
1. Read `docs/human-tasks/factcheck-test-NN.md`: every `wynik`/`uwagi` cell.
2. Each bug or proposal goes to the spec first: a ⬜ rule or a ticket in `zgloszenia/`. A ❌ on a still-open branch means `fix NN`, not a new `task_NN.md` (`/spec-tasks` makes tasks from accepted spec text). Ask Roland which; don't fix silently.
3. When nothing is left open, `git mv` the sheet to `docs/human-tasks/done/` (after `git ls-files --error-unmatch`, as in **implement** step 7) and fix its relative links.

Never move an unfilled sheet without Roland's waiver: the `Zwolnienie:` line the dashboard writes on his click. If he waives it in chat, quote him in the task report (`Roland, czat <date>: …`), ask him to press "Zwolnij z testu", and move the sheet only after the line exists. You never write the `Wyniki człowieka`, `Zwolnienie` or `Zamknięcie` lines.

A sheet that holds several tasks (`## Część: task_NN`) is read and closed as a whole: every part's `wynik` cell counts, and all its tasks close with it. Roland can also close an unfilled sheet in the dashboard ("Przenieś arkusz do done/" with a confirmation): the dashboard then writes `⏭ pominięte (zamknięcie bez wypełnienia)` into the empty fields and the `Zamknięcie: … pominięte N z M pól` line. That is closing without full verification, not a waiver, and ⏭ is never evidence; you never do it yourself.

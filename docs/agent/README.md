## Systems
- **Player** (`player.gd`): FPS `CharacterBody3D`, **capsule r=0.35 m h=2 m** (the cave arm has ~1 m squeezes, so don't make it wider), `floor_max_angle` 55° and `floor_snap_length` 0.3 so it rides over rails and lips. Head yaws → EyeCamera pitches (40° up / 70° down) → `InteractRay` 2.5 m + `Lamp` (a warm OmniLight the player carries). Emits `focus_changed` / `interacted`. It is in the `persist` group.
- **Interactable** (`interactable.gd`, `Area3D`): add it as a child of a prop, then set `display_name` and `description`. It fits its own box shape (and, with `solid`, a StaticBody) to the prop's meshes when the scene starts, and highlights them with `shader/interact_highlight.gdshader` as `material_overlay`.
- **HUD** (`hud.tscn`): crosshair, "[E] name · cost" prompt, description panel (E closes it and never re-uses the object; texts of objects that vanish when used are pinned for 12 s), the hero's condition in the corner, toasts (time in minutes: "−15 min · Rozmowa z Teklą"), and the sanity vignette. **No clock on the HUD** since task_09: the time is in the notebook ("Czas" tab) and the VN window. (`shader/sanity_vignette.gdshader`, only on the "na_krawedzi" band). `world.gd` connects it to the player.
- **GameState** (`game_state.gd`): the whole run state and its helpers for dialogues (`has_flag`, `done_today`/`mark_today`, `give_item`, `give_to_npc`, `use_item`, `quest_log`, `change_rep`, `sanity_band`, `can_afford`, `npc_place`, `veins_mapped`, `quota_text`, `veins_acc`, `days_left_text`, `vein_hint`, `mark_veins_for_player`, `request(action)`, `bump_flag`…). Time: `advance_time` logs every action in `time_log` (day → entries, saved); `add_quiet_time`/`commit_time` let the VN charge a conversation per option and log it once; `duration_text()` ("5 min", "1 h 20 min"). `FIXED_SANITY` (Hrapek) never changes. The week: `LAST_DAY = 8` (Racibor counts on that morning), `QUOTA = 12` veins by the end of `QUOTA_DAY = 7`. Day 06:00–22:00 (16 h). The hero: `player_health`, `player_sanity`, `player_fever` (bands in words; death only on top of earlier wounds) and `player_fatigue` (task_12: +8 %/h in the tunnels, incl. walking via `travelling`, +2 %/h in the camp, sleep −60, the campfire −15 via `rest_by_fire()`; words from 75 %; at 100 % `is_exhausted()` doubles every walk onwards). `expedition` holds the trip under way. Constants aren't visible in dialogues: use helper functions (`quota()`). **task_14:** `has_arrived(id)` (NPC-18; `ARRIVAL_FLAG`: Sabina from `sabina_joined`, Ottokar/Hieronim/Welf from `drudzy_met`, derived from the flags, nothing saved) keeps the nightly sanity losses and the night-5 tremor off anyone who has not arrived; `dawn_log` (one entry per dawn from `reset()` and `start_next_day()`: veins, the hero, every character, flags new since the last dawn) and `vein_log` (each vein with its day, its hour and "n", how many veins were on the map with it: the quota time and the numbering come from "n", not from the position, because the log of a save from before version 6 starts late) feed the run report and are saved (ZAP-12); the band helpers have value forms (`health_band_of`, `mind_band_of`, `sanity_band_of`, `trust_band_of`, `fatigue_band_of`) so a stored number can be put in the notebook's band.
- **Run report** (`run_report.gd`, `class_name RunReport`; task_14, ZAP-11 / CZAS-16): `collect(ending)` reads GameState (time log sorted into the nine categories by label — `categorize()`, dawn log, vein log, final flags as "key choices"), `to_markdown()` / `to_json()` render it (a person's band words follow `NpcData.female` through `FEMININE`, and a fever replaces the health band, as in the notebook), `write(ending)` puts `przebieg-<date>_<time>.md` and `.json` under `user://raporty` (Windows: `%APPDATA%\Godot\app_userdata\Everhorror\raporty`) and returns the `.md` path. Triggers: `StoryDirector._week_end()` (both endings, just before the end screen, which names the file) and the SAVE REPORT button in the pause menu ("w trakcie"). Death writes none. **Play time (task_20, G5):** the time table has a last column "czas realny dnia" (mm:ss, "—" without data) and a total under it; the JSON has `played_ms` / `played` per day (`days[].time`) and `played_total_ms` / `played_total`. The data is `GameState.play_ms` (the current day, ms; `_process` → `play_tick()` adds a frame only while the gameplay scene is current and the tree is not paused, so the main menu and the pause menu do not count while dialogues, the map and the notebook do; one frame adds at most 1 s), moved by `start_next_day()` into the `played_ms` field of the `dawn_log` entry of the day that ended (a repeated `record_dawn()` keeps it) and saved as the optional top-level `play_ms` (`SAVE_VERSION` stays 6; a save without it loads as -1 = no data for that day, the report shows "—"). `SaveManager.retry_morning()` keeps the counter as it was at death (`restore_play_time()`: it already counts on from the snapshot, so nothing is added twice). `play_frozen` (set by `ScreenFade.show_end()`, cleared by `reset()`/`load_state()`) stops it on the end screens, which do not pause the tree. Loading another slot in the middle of a day, or quitting without saving, loses the play time since the last save (the normal load semantics): a lower value in the report is not a bug. Frames are summed with a sub-millisecond remainder (`_play_acc`), so the frame rate does not skew the total. Tests without a world (`unit`, `balance`) never tick it, so their reports say "—" and saves stay reproducible. A **new time label** (a `time_reason`, an `advance_time(…, "label")`) must be added to `RunReport.LABEL_CATEGORY` / `PREFIX_CATEGORY`, or `lint` fails. Nothing leaves the machine.
- **VN** (`vn.gd` + `scene/vn/vn_balloon.tscn`): Dialogue Manager balloon with a live 3D portrait of the speaking NPC (own world in a SubViewport) or a static portrait (`STATIC_PORTRAITS`, e.g. the wall). Modal while open. Dialogues request world actions (`sleep`, `blast`) that run after the dialogue closes.
- **NPCs**: `NpcData` card → `Npc` node in `world.tscn/NPCs` (model, collision, "talk" interactable — opening is free, `VN.TALK_MINUTES` = 5 min for every picked response except `[#leave]` farewells, `[#free]` hand-overs and a response already picked before with the same person (`GameState.asked`, saved; factcheck 10); a response whose follow-up spends time of its own (`advance_time`, or `request()` such as the blast) gets its 5 min back; the VN clock moves per option and one toast/log entry sums the conversation on close; scene dialogues via `VN.play` never charge). The VN shows responses locked only by trust or an item greyed out with the reason (`ResponseLock`, `vn_balloon.visible_responses()`, option "Show locked choices") → `CharacterModel` (Quaternius parts on one retargeted skeleton, male or female body, hidden parts, head attachments such as the iron mask, looping work poses). `CampSchedule` (`camp_schedule.gd`) says where each NPC is by day, hour and story flags; markers are in `camp.tscn/Markers`.
- **StoryDirector** (`story_director.gd`, node `Story` in `world.tscn`): intro, applying the schedules (camp and field; a short fade when someone moves in the camp), expeditions (depart, [M] onwards, return with `ExpeditionSummary`), Drudzy encounters (the day-3 meeting, then rolls on arrival kept in the `encounter_place`/`encounter_npcs` flags), Mirosław's blast, nights (sanity, Nasir's fever, departures, Mirosław's death, the tremor, the hero's rest/fever, deciphering, the Fourteenth's lamp, dreams), mornings (morning snapshot + AUTO autosave, day-3 announcement, Racibor's reminders), the campfire evening seat (`Camp/CampProps/Campfire/SeatUse`, enabled 20:00+, once a day, plays `dialogue/ognisko.dialogue`), the hero's death (retry from the morning) and breakdown, the week end (two endings), and in the opening the closing scene on day 3 (task_37). Location id while away is the `location` flag (`GameState.current_place()`).
- **Expeditions**: `LocationData` + `Expeditions` (graph, shortest path through places that are open now, falling back to the blocked shortest one so `route_lock` can say what's in the way; known/locked places, trip cost: edges (×2 when exhausted) + 1 h scouting on the first visit + 1 h per leg when wounded; the way back to the camp is `Expeditions.return_hours()` = half of `expedition.outbound_hours` (the legs actually walked since leaving the camp), rounded up to 5 min, never doubled (task_12); requirements `flag:`, `noflag:`, `item:`). `MapScreen` has two modes: TABLE (the map table in the camp, "WYRUSZ") and FIELD ([M] or a signpost: neighbours or back to the camp). `map_drawing.gd` draws the graph. 25 veins (`vein_<id>` flags), 3 of them under flowstone (need the pickaxe).
- **Items / screens**: `ItemData`; `InventoryScreen` [I] (use medicine, the hero's state in words); `ExpeditionSummary` after each return; `Notebook` [J] (quests with the quota line, notes, people: health/mind/trust in words, and "Czas": the clock, hours to night, the time log per day). `Interactable` supports `opening_name` / `opening_description` (texts that name an absent person get a neutral version in the opening; `shown_name()` / `shown_description()`), `required_item`/`consume_item`/`missing_text`, several items per pickup (`"bandaze:2,swieca"`), `wound`, `sanity_change`, `expedition_event`; the player checks `blocked_reason()` before using.
- **The three-day opening** (task_37, spec `04_tresc/otwarcie.md`, OTW-1…OTW-10): START in the main menu calls `SaveManager.new_game()`, which sets the flag `opening`; FULL WEEK (OLD DEMO) calls `new_game(true)` (no flag) and plays the week as before. A save without the flag is the week. `GameState.opening()`, `deferred(id)` (`OPENING_DEFERRED`: everyone except Racibor, Bolko, Mirosław and Tekla) and `OPENING_PLACES` (east, west, upadowa; `Expeditions.in_chapter()` hides the rest from the map, the routes and the field map). Deferred people are never placed (`CampSchedule`, `FieldSchedule`), never "arrive" (`has_arrived`, so nights leave them alone), no Hrapek, no Drudzy roll, no Nasir fever, no Dobrawa. The cipher is not read in the night: Bolko's `papers` (trust ≥ 0) or the bed's `papers_alone` in `system.dialogue` (three steps, flags `deciphered`, `papers_with_bolko`, `bolko_guilt`, quest entry `slady`/`nizej`). Mirosław's "Jak się trzymasz?" has three one-hour ways in both variants (`mir_support` = robota/cisza/nazwane, answered on a later day via `GameState.earlier_day()`). Tekla's `supper` (18–20, once a day, `supper_*` flags). On day 3 the closing scene (`drudzy.dialogue` `finale`, flag `opening_maps` = pokazane/odmowa/zwloka) comes when the hero is in the camp from `OPENING_FINALE_HOUR` (18:00), or when he answers "Tak, idę spać" at the bed (the bed asks "Kładziesz się?" first, so `papers_alone` stays reachable); `StoryDirector._opening_finale()` pushes a modal at once (the pause menu and so a save stay shut until the end screen), writes the run report (`RunReport.ENDING_OPENING`, "Koniec otwarcia") and shows the end screen; no night follows. Tests start the full week unless `start_world(setup, true)`.
- **Schedules**: `CampSchedule` (camp places by day/hour/flags; `gone`/`dead` NPCs never appear) and `FieldSchedule` (miners at work in `<Place>Work` markers, Drudzy in `<Place>Spot1..4`). An NPC met in the field has place `"teren"`. **Day 1 (task_10):** only Mirosław, Bolko, Tekla and Racibor are in the camp; `GameState.FIRST_MEET` (Wszebor, Nasir, Hagiwara, Sobek, Anzelm) are on a shift in `FIRST_ROOMS` (east, rzapie, west), rolled once per new game into the `first_room_<id>` flags, at most 2 to a room, on `<Place>Spot1..2`, all day 1; from day 2 the usual schedule. Scenes use `in_camp_today(id)` (not `npc_status == "camp"`) for who is around.
- **Locations** (`locations.tscn`, generated by `tools/generators/gen_locations.gd`, far away from the mine): Rzapie (-60, 0, 70), Upadowa (-60, 0, 110), Kaplica (60, 0, 110); task_05 places on a grid: z 150 (Wyrobisko -100, Pompy -50, Grota 0, Kostnica 50, Galeria 100) and z 200 (Kuznia -100, Przekop -50, Zalany 0, Szczelina 50, Szyb 100), each a chamber built by the `chamber()`/`stub()` template with the entry from the west. Markers in `Locations/Markers`: `<Place>Entry`, `<Place>Spot1..4`, `<Place>Work`. Signposts `*ExitUse` open the field map. The east/west places live in the main level (veins in `gen_mine_deep.gd` / `gen_camp.gd`, spots `EastSpot*`/`WestSpot*`). `RiddleWall` (`riddle_wall.gd`) animates the chapel wall when the `wall_open` flag is set (after the dialogue closes).
- **Menus**: `main_menu.tscn` (START = the three-day opening / FULL WEEK (OLD DEMO) / OPTIONS / LOAD GAME / EXIT, and a dimmed "0.5.3 · spec 27e91e7" label bottom right from `BuildInfo.label()`, UI-6: the version is in the main menu only) and `pause_menu.tscn` (a CanvasLayer that runs while the game is paused: RESUME / SAVE GAME / LOAD GAME / OPTIONS / SAVE REPORT / MAIN MENU / EXIT; SAVE REPORT writes the run report and shows its path in English under the buttons, UI-7). Both reuse `options_panel.tscn` and `save_slots_panel.tscn`. `BuildInfo` (`build_info.gd`) holds the stamped `SPEC_SHA` ("unknown" until `tools/release/stamp_build.js` has run) and reads the version from the project settings.
- **Save/load**: `SaveManager.save_game(slot)` saves `save_state()` from every node in the `persist` group, keyed by node path. `load_game(slot)` changes scene, and the scene calls `SaveManager.restore_pending(self)` in `_ready`. New stateful nodes: add them to the group and implement `save_state` / `load_state`. `SAVE_VERSION = 6` (v4: the time log; v5: asked options and fatigue; v6, task_14: `dawn_log` and `vein_log` for the run report; older saves still load, with an empty log, nothing asked, no fatigue and empty report logs — the report then says "brak danych"). `capture_morning()` keeps the dawn state in memory AND writes it to disk as the AUTO slot (`AUTO_SLOT = 0`, `auto.json`, load-only in the UI); `retry_morning()` restarts the day after a death. The folders are `SaveManager.save_dir` (`user://saves`) and `report_dir` (`user://raporty`, used by `RunReport.write()`); under a test run they point into the test folder (`EVERHORROR_TEST_DIR` / user arg `--test-dir=`, `isolate_for_tests()`; tools/README.md#testy), so a test never touches the player's saves. Fixtures of every save version still supported: `tools/tests/fixtures/saves/v3.json`…`v6.json` (add the next one when `SAVE_VERSION` changes).

## MCP servers
Configured in [.mcp.json](../../.mcp.json).

Machine-specific paths. uv tools live in `C:/Users/grups/.local/bin`. Windows **Smart App Control is ON**: it blocks unsigned DLLs (e.g. pywin32's `win32job`) in some Python packages. Python MCP servers on the `mcp` 1.10–1.x library crash on import, so pin `mcp==1.9.4` or use `mcp>=2.2`. Never try to bypass the policy.

### `godot` — `@coding-solo/godot-mcp` (no editor needed)
- Runs the game without the editor: `run_project` → `get_debug_output` → `stop_project` for a smoke test after changes. Always call `stop_project`.
- Also `create_scene`, `add_node`, `save_scene`, `load_sprite`, `get_uid`, `update_project_uids`. The project path is `C:/dev/gamedev/everhorror/everhorror`.

### `godot-editor` — hybridindie `godot-editor-mcp` (needs the Godot editor open)
- The editor addon `addons/godot_mcp` dials `ws://127.0.0.1:9080`. The `MCPRuntimeProbe` autoload enables runtime inspection and does nothing in exports.
- Start with `godot_health_check` (`bridge_connected` must be true; if false, ask the user to open the editor) and `godot_get_server_info`.
- Only `core` and `inspection` are on by default. Enable more with `godot_enable_toolset(category=...)`, e.g. `scene_edit`, `scripts`, `runtime` (play scene, live scene tree, input simulation), `testing` (assert node properties at runtime), `editor` (screenshots), `physics`, `scene_3d`, `navigation`. Mutations support `dry_run` and `godot_undo`.
- Known issue: `godot_editor_capture_screenshot` timed out while the editor window was idle in the background. Retry with the editor in front.
- Full docs: https://hybridindie.github.io/godot-mcp/llms-full.txt

### `godot-runtime` — Erodenn `godot-mcp-runtime` (runs the real game, no editor and no addon)
- Added 2026-09-25 (task_07; npm, MIT, Node — safe under Smart App Control). `GODOT_PATH` in `.mcp.json` points at the **windowed** exe.
- `GODOT_MCP_DISABLE_ELICITATION=true` is set (user decision, 2026-09-25): the VS Code extension can't show MCP confirmation prompts, so without it every `run_project` is auto-declined ("User declined run_project") even though the user saw nothing. If that error appears, the server was started without this env — ask for an MCP reconnect; don't blame the user.
- **Always `run_project` with `background: true`** (user rule: tests must not take over the mouse and keyboard). Never fall back to `attach_project` + a manually launched window for routine tests — it has no background mode and the world scene captures the mouse.
- `run_project` injects a transient McpBridge autoload (nothing committed; artifacts under `.mcp/godot-runtime/` are cleaned up). With `background: true` the window parks off-screen with physical input blocked while simulated input, screenshots and runtime tools keep working.
- Tools: input simulation (keys, mouse, `click_element`, input actions, waits), screenshots (inline 960×540 + full PNG), UI discovery, live scene tree.
- **This is the only path that exercises the real input map end to end** (E/I/J/M, ui_accept, mouse) — the headless suite drives GameState/VN directly and never touches bindings. Use it for E2E smoke ("press M → the field map opens"), reproducing input bugs and live UI screenshots; logic regressions stay in `tools/run_tests.sh`. Windows paths: forward slashes.

### `blender` — `mcp-for-blender` (needs Blender 5.2 open with "Start MCP Server" clicked)
- Addon `blender_mcp.py` is installed and enabled in Blender. Press N in the 3D viewport → "MCP for Blender" tab → Start/Connect.
- Useful for simple props, Poly Haven (CC0) search and download, viewport screenshots, `export_scene` → export glTF into `assets/`. Telemetry is disabled.

### `freesound` — timjrobinson/FreesoundMCPServer (`C:/dev/tools/freesound-mcp-server`)
- Needs the user env var `FREESOUND_API_KEY` (free at https://freesound.org/apiv2/apply). Without it, calls fail.
- Search and metadata only (no OAuth). Fetch the public preview MP3 URL with curl. Record new sound/licence entries in `../specification/06_oprawa.md`; the licence proof per pack is listed there too. Prefer CC0.

## Technical glossary
World terms (błękitne żelazo, Pierwsi / Pierwszy, Drudzy, Oni, Ekspedycja, Kniaź Jaksaru, the Wąwóz, sanctin, Exitium, the places and the people) are defined in the specification: `01_swiat/slowniczek.md`, `01_swiat/swiat.md`, `04_tresc/miejsca.md` (place ids and the graph), `02_postacie/`. Only terms that name something in the code stay here.
- **obóz** — the camp (hub): `camp.tscn`, `CampSchedule`, `in_camp_today(id)`. An NPC met in the field has place `"teren"`.
- **szychta** — a mining shift. On day 1 the `GameState.FIRST_MEET` characters are "on a shift" in `FIRST_ROOMS`.
- **poczytalność / sanity** — an NPC's sanity meter (`sanity_band`, `FIXED_SANITY`, `has_arrived`). The hero has `player_sanity`.
- **Ekspedycja** — the player's group and also a faction value in `NpcData`: Drudzy / Ekspedycja / Inna ("other"). No more factions are planned.
- **„Czternaście kresek” / the Fourteenth** — the task_06 mystery quest `czternasty`: tally marks, Grabiec's notebook, the bread/lamp/niche/medal clues (`GameState.FOURTEENTH_CLUES`); at ≥ 4 clues someone leaves the hero the old guide's lamp at night. The demo never says who; preserve that ambiguity and route unresolved canon to Roland.
- **[ROBOCZE]** — working text written by the agent, waiting for Roland's review. Only Mirosław comes from the GDD; the other demo characters are working characters. Ren and Vitav are outside the active process since 2026-10-26 (current ownership: Roland).
